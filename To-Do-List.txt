To-Do List
==========
Ideas and planned work. Place any suggestions not implemented by the user here.

Legend: ID [Model | Risk n/5]
  Model = which model should do the task (Sonnet = mechanical/contained, Opus = design judgement or cross-file reasoning).
  Risk  = chance a fix breaks something or causes errors (1 = trivial, 5 = very likely to need debugging).

Measure before and after each performance item with npm run perf (see G10 in section H).
Watch out: the world comes from one seeded rng, so adding, removing or reordering rng()/R()/pick()
calls in alley.js, signs.js or batch.js changes the whole layout. Refactors there must keep the draw order.

B. Runtime performance (highest impact first)
---------------------------------------------
B1  [Opus   | Risk 3/5] ground.js: bake the snow/puddle masks into a texture. They never change, but every ground pixel
    recomputes them each frame (3 gfbm x 5 octaves + 1 gvn = about 64 hash calls). Only the ripple needs uTime.
B2  [Opus   | Risk 3/5] batch.js: split merged meshes into z-sections of the alley. Each material is now one mesh spanning
    the whole scene, so frustum culling almost never removes anything.
B3  [Opus   | Risk 3/5] ground.js / atmosphere.js: use layers to leave snow, steam and the distant skyline out of the
    reflection pass, which redraws the full scene. Snow also uses the main-view uScale, so flakes are oversized in the
    smaller target.
B4  [Opus   | Risk 4/5] signs.js: put signs in a texture atlas and draw them as one mesh with a per-sign flicker attribute.
    There are 23 separate meshes, materials and canvas textures, all drawn again in the reflection pass.
B12 [Sonnet | Risk 2/5] main.js resize: stop adaptive scale from softening reflections. refl.setSize uses the scaled drawing
    buffer, so on High a 60% step leaves the reflection at 30% of native width and height. Size it from the unscaled
    pixelRatio, or give it a floor. This costs frame time, since the reflection pass redraws the full scene; check with npm run perf. Investigate if actually a bug.

C. Load time and memory
-----------------------
C1 [Opus   | Risk 4/5] textures.js / pbr-textures.js / noise.js: move texture generation to a Web Worker. Loops block the main thread and only
   yield between textures. Concrete costs 14 octaves x 4 hashes per texel, about 235M hash calls at 2048 x 2048.
   (Canvas-drawn parts such as the shutter graffiti must stay on the main thread.)
C4 [Opus   | Risk 3/5] texture-core.js: use DataTexture where no canvas drawing is needed (only shutter draws afterwards).
   Canvases stay alive through texture.image, keeping an extra CPU copy of each map. genCloud also loses alpha precision
   to canvas premultiplication. Watch flipY and colour space, which differ between CanvasTexture and DataTexture.
C5 [Sonnet | Risk 3/5] batch.js: stop cloning geometry for every prop (compute into a preallocated buffer), and dispose the
   TubeGeometry that tube() creates, since Batch.add clones it and discards the original. Never mutate the shared
   primitives in makeKit.

F. Bugs found during the review
-------------------------------
F1 [Opus   | Risk 3/5] player.js / ui.js: touch detection is true on any touchscreen laptop, which disables pointer lock, and
   mouse look requires pointer lock, so the mouse can't look around on those devices. Choose the mode from the input
   actually used (pointerType).
F4 [Sonnet | Risk 2/5] style.css title screen: on short viewports the ENTER button is off screen and can't be reached, since the
   page has overflow: hidden. At 640 x 360 (a landscape phone) its top is at y = 416. Touch devices have no Enter key to fall back on.
F7 [Opus   | Risk 2/5] adaptive-scale.js: it can't tell a slow GPU from a capped display. A browser held to 30 FPS (battery saver) drops to
   60% and stays there, even if the GPU has room to spare. Consider detecting a steady cap, or measuring GPU time (see G14).
F6 [Opus   | Risk 2/5] Touch devices never see the pause menu (it only exists with pointer lock), so they can't change quality or mute
   from it. Touch users have the HUD sound button but can only change quality on the title screen.
